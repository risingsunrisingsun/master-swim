# ADR-0012: 네이버 로그인 — 명단 이름과 같으면 자동 연결, 아니면 운영자 승인

- 상태: 채택
- 날짜: 2026-10-09
- 보완: ADR-0011 (초대코드 · 이름 + 비밀번호는 그대로 남는다)

## 맥락

초대코드 · 비밀번호 방식은 운영자가 회원마다 코드나 비밀번호를 만들어 보내야 하고,
비밀번호 분실도 운영자 몫이다. 나인틴 회원은 모두 네이버 카페 회원이라 네이버 계정이 있다.

네이버 로그인으로 알 수 있는 것은 **"네이버 계정이 있다"** 뿐이다. 네이버 카페 API 는 카페 가입 ·
글쓰기만 있고 **특정 카페의 회원인지 조회하는 기능이 없다.** 네이버 로그인만으로 들이면
네이버 계정이 있는 누구나 회원 기록을 보게 된다.

## 결정

1. 앱은 네이버 **웹** 로그인(OAuth 2.0)을 쓴다. iOS SDK 는 네이티브 앱용이라 이 PWA 와 맞지 않는다.
2. Edge Function `naver-login` 이 code → 토큰 → 프로필(고유 id · 실명 · 별명 · 성별 · 출생연도)을 받고
   명단과 잇는다. Client Secret 은 함수 환경변수에만 둔다.
3. **자동 연결:** 네이버 실명이 명단의 이름(`display_name`)과 **똑같고**, 그 회원이 사용 중지가 아니고
   **아직 네이버에 연결되지 않았으면** 잇는다. 명단은 운영자가 확인한 사람들이다(운영진 결정).
   이름은 유일하므로 맞는 회원은 많아야 한 명이다.
4. **그 밖에는 가입 신청**(`join_requests`)으로 남는다. 운영자가 [운영] → 회원에서 "새 회원으로 추가"
   또는 "명단의 회원과 연결"로 승인하거나 거절한다. 동명이인 표시(`김민수A`)처럼 이름이 다른 기존
   회원은 여기서 잇는다. 거절한 계정은 다시 들어와도 신청이 새로 생기지 않는다.
5. 회원이면 함수가 Auth 사용자를 (없으면 만들어) 잇고 **일회용 로그인 토큰**(magic link 의
   hashed_token)을 돌려준다. 앱이 `verifyOtp` 로 세션을 받는다. 메일은 오가지 않는다.
   비밀번호로 쓰던 회원도 같은 Auth 사용자라 기록 · 출석이 그대로다.
6. 성별 · 출생연도는 운영자가 비워 둔 칸만 네이버 값으로 채운다.

## 결과

- 운영자가 할 일: 명단 이름 입력 + 자동 연결되지 않은 신청 승인. 초대코드 · 비밀번호 발급과
  분실 처리가 거의 없어진다.
- **위험:** 명단에 있는 사람과 실명이 같은 비회원이 먼저 네이버로 들어오면 그 자리에 이어진다.
  이미 연결된 회원은 가로챌 수 없고(3), 잘못 이어지면 운영자가 회원 화면에서 **"네이버 연결 끊기"**로
  되돌린다. 30~100명 동호회에서 감수한다(운영진 결정).
- 네이버 개발자센터 앱은 "개발 중" 상태에서 **등록한 테스터 ID 만** 로그인된다. 모든 회원에게 열려면
  네이버 검수를 받아야 한다.
- iOS 홈 화면(PWA)에서는 로그인 중 사파리로 넘어갔다 돌아오지 못하는 문제가 알려져 있다. 막히면
  사파리에서 한 번 로그인한 뒤 홈 화면 앱을 쓰게 안내한다.
- `NINETEEN_NAVER_CLIENT_ID` 가 비어 있으면 네이버 버튼 없이 빌드된다. 이름 + 비밀번호 로그인은
  전환 기간 동안 남긴다.
