# ADR-0010: v2 는 데이터를 Supabase 에 두고 회원과 운영자가 나눠 본다

- 상태: 채택
- 날짜: 2026-10-07
- 대체: ADR-0004 (서버 없는 정적 PWA) — **v2 에 한해서.** v1 은 그대로 남는다.
- 근거: PRD-0001

## 맥락

v1 은 기록이 기기 밖으로 나가지 않는 개인 도구였다(ADR-0002, 0004). v2 의 세 기능 중
두 개가 그 전제로는 성립하지 않는다.

- 기능2 — 정기모임 기록을 **운영자가** 넣고 **회원이** 본다.
- 기능3 — 출석을 **운영자가** 체크하고 **회원이** 달성률을 본다.

한 사람이 쓰고 다른 사람이 읽으므로 공유 저장소가 있어야 한다.

## 결정

- 화면은 지금처럼 **GitHub Pages 의 정적 PWA** 로 둔다. 빌드·배포 파이프라인을 다시 쓴다.
- 데이터와 인증은 **Supabase**(Postgres + Auth + Edge Function) 무료 티어에 둔다.
- 접근 제어는 **Postgres 행 단위 보안(RLS)** 이 한다. 화면이 숨기는 것은 보안이 아니다.
  회원은 자기 행만, 운영자(`role = 'admin'`)는 전부를 읽고 쓴다.
- 앱은 `Backend` 인터페이스 하나만 본다. 구현이 둘이다.
  - `SupabaseBackend` — 실제 운영.
  - `LocalBackend` — localStorage 위의 **데모 모드**. Supabase 설정이 비어 있으면 이것이 뜨고
    화면 위에 "데모" 띠가 붙는다. 서버 없이 화면과 흐름을 검토하고 테스트하기 위한 것이다.

## 결과

- **신체 데이터는 받지 않는다.** ADR-0002 의 "신체 데이터는 기기 밖으로 나가지 않는다"는
  v2 에서 "애초에 받지 않는다"로 계승한다. 서버에 가는 것은 이름 · 기록 · 출석뿐이다.
- 무료 티어는 **1주일 동안 요청이 없으면 프로젝트를 일시정지**한다. 정기모임이 매주 있으면
  걸리지 않지만, 방학처럼 쉬는 달이 있으면 운영자가 대시보드에서 재개해야 한다.
- anon 키는 공개 저장소에 들어가도 된다(RLS 가 지킨다). **service_role 키는 Edge Function
  환경변수에만** 둔다.
