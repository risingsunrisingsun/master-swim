# ADR-0002: 신체 데이터는 기기를 벗어나지 않는다

- 상태: 채택
- 날짜: 2026-07-26

## 맥락

팀 요구사항이 서로 당긴다.

- 코치는 회원 기록을 대시보드로 봐야 한다 → 서버 필요
- 일부 회원, 특히 여성 회원은 키·체중·골격근량 제공을 꺼린다 → 서버에 두면 안 됨

한편 기록은 이미 팀 네이버 카페에 공개되고 있어 민감도가 다르다.

## 결정

데이터를 두 계층으로 나누고 저장 위치를 다르게 한다.

| | 기록 데이터 | 신체 데이터 |
| --- | --- | --- |
| 항목 | 종목 · 거리 · 기록 · 스플릿 · 스트로크수 · 연령대 · 성별 | 키 · 윙스팬 · 체중 · 골격근량 · 건강 문항 |
| 위치 | Supabase (2차부터) | 기기 localStorage 전용 |

**신체 데이터는 서버 테이블에 컬럼 자체를 만들지 않는다.** 전송하는 코드를 두지 않는다.

## 결과

"보지 않겠다"는 정책이 아니라 "받을 수 없다"는 구조가 된다. 화면에 "이 값은 이 폰을
벗어나지 않습니다"라고 쓸 수 있고, 그것이 사실이다. 동호회에서 체성분 입력을 꺼리는
회원에게 정책 문구는 먹히지 않고 구조만 먹힌다.

신체 데이터 없이도 **훈련 처방과 병목 진단은 전부 작동한다.** 잠기는 것은 식단과
체형 슬라이더뿐이다. 미입력이 앱을 빈 화면으로 만들지 않도록 각 기능이 개별적으로
저하되어야 한다.

연령은 5세 단위 연령부만 받는다. 마스터즈 대회가 그 단위로 나뉘어 사실상 공개
정보인 반면, 생년월일은 그렇지 않다.

건강 문항도 같은 이유로 로컬에 둔다. 다만 1차에서는 문진 자체를 두지 않고
경고 문구만 둔다(CONTEXT.md · 안고 가는 위험).
