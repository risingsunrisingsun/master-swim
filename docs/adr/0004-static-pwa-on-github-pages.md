# ADR-0004: 정적 PWA 를 GitHub Pages 로 배포한다

- 상태: 채택
- 날짜: 2026-07-26

## 맥락

회원 20~30명이 각자 폰으로 쓴다. 호스팅 비용 없이 가야 한다. 그런데 30명 규모는
어떤 무료 티어도 넘기지 못하므로, 실제 제약은 비용이 아니라 **책임**이다 —
서버에 개인 데이터를 모으면 백업·유출·탈퇴처리가 전부 관리자 숙제가 된다.

수영장에는 와이파이가 없다.

> **정정 (2026-07-30)**: 수영장에 와이파이가 들어왔다. 오프라인 동작은 이제 제약이 아니라
> 부수 효과다. 결정은 바뀌지 않는다 — 정적 PWA 와 앱 셸 캐시는 비용·책임·설치 가능성만으로도
> 여전히 옳다. 네트워크는 탈의실·주차장에서 끊기고 폰 데이터를 아끼는 회원도 있다.

## 결정

- **정적 PWA.** bun + TypeScript, 프레임워크 없음. 화면 수가 적고 계산이 전부
  순수 함수라 프레임워크가 벌어주는 것이 적다.
- **GitHub Pages.** 무료 티어는 공개 저장소를 요구하지만, 저장소에 들어가는 것은
  코드와 방법 카탈로그뿐이다. 개인 데이터는 애초에 서버 밖이다(ADR-0002).
- **서비스워커로 앱 셸을 캐시한다.** 첫 방문 이후 네트워크 없이 뜬다.
- 1차에는 서버·로그인이 없다. 데이터는 localStorage 에만 둔다.

## 결과

Pages 는 `/<repo>/` 하위 경로로 서빙하므로 **산출물의 모든 참조가 상대경로여야 한다**
— `index.html`, manifest, 서비스워커 등록 전부 `./` 로 시작한다. 절대경로 하나가
섞이면 로컬에서는 되고 배포에서만 깨진다.

기기를 바꾸거나 브라우저 데이터를 지우면 입력이 사라진다. **JSON 내보내기/가져오기가
선택이 아니라 필수 기능**이다(`src/storage.ts`).

2차에서 Supabase 를 붙일 때 노출되는 anon key 는 RLS 를 전제로 공개 설계된 키이므로
공개 저장소에 커밋해도 무방하다. 단 service_role key 는 절대 들어가면 안 된다.
