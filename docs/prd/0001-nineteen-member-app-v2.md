# PRD-0001: 나인틴 회원 앱 v2 (전면 개편)

- 상태: **초안** (검토 대기)
- 날짜: 2026-10-07
- 기존 앱(v1.5, 정적 PWA)을 참고 자료로만 쓰고 처음부터 다시 설계한다.

## 1. 배경과 목적

회원제 카페(나인틴)의 회원이 **로그인해서 자기 현황을 확인하는 앱**이다.
v1.5는 목표 페이스에서 주간 플랜 전체를 생성하는 도구였고, 서버·로그인이 없어
다른 사람이나 운영자와 데이터를 나눌 수 없었다. 회원이 실제로 열어 볼 이유는
세 가지로 좁힌다.

1. 내 기록을 줄이려면 **무슨 운동을 몇 세트** 해야 하나
2. 내 기록이 **어떻게 변해 왔나**
3. 이번 달 나인틴 훈련에 **얼마나 나왔나**

한 줄 정의: **"내 기록, 내 훈련, 내 출석을 한 화면에서 보는 나인틴 회원 전용 앱"**

## 2. 사용자

| 역할 | 하는 일 |
| --- | --- |
| 회원 | 로그인, 기록 입력, 세트 처방·추이·달성률 열람 (본인 것만) |
| 운영자 | 회원 명단·초대코드 관리, 정기모임 생성, 출석 체크, 모임 기록 입력, 코치 계수 조정 |

운영자는 회원 데이터를 모두 볼 수 있다. 회원끼리는 서로의 데이터를 볼 수 없다.
(기존 열람 권한 원칙 "훈련 로그는 코치만"을 유지한다.)

## 3. 범위

### 만든다
- 로그인 (초대코드 + 이름/비밀번호)
- 기능1: 기록 단축 세트 처방
- 기능2: 내 기록 추이 (개인 입력 + 운영자 입력)
- 기능3: 나인틴 훈련 참여 달성률
- 운영자 화면: 명단, 모임, 출석, 기록 입력, 계수 조정

### 만들지 않는다 (v1에서 가져오지 않음)
주간 플랜 생성, 식단, 어록, 용어 퀴즈, 지상훈련 영상, 병목 진단, 랭킹·대회 일정
(마이랭킹과 카페가 이미 한다), 회원 간 기록 비교·공개 랭킹.

### 범위 제한
25m 단수 수영장, 50m·100m, 자유형·배영·평영·접영 (개인혼영은 기록 보관만).
v1의 범위를 그대로 이어받는다.

## 4. 기능 요구사항

### 4.0 로그인
- 운영자가 회원을 등록하고 **초대코드**를 발급한다. 코드는 1회용, 유효기간 7일.
- 회원은 초대코드로 가입하며 **이름 + 비밀번호**를 정한다. 이후에는 이름 + 비밀번호로 로그인한다.
- 동명이인이 있으면 운영자가 표시명(예: 김민수A)을 구분해 등록한다.
- 비밀번호 분실은 운영자가 재설정 코드를 발급한다. 이메일·전화번호는 받지 않는다.
- 로그인한 회원·운영자는 **내 계정**에서 지금 비밀번호를 확인받고 스스로 바꾼다.
- 초기에는 운영자가 명단을 일괄 입력하며 **초기 비밀번호를 정해 준다**(ADR-0011 보완). 회원은 첫 로그인 뒤 바꾸라는 안내를 받는다.
- 성별 · 출생연도는 **운영자가 입력하는 선택값**이다. 기존 회원은 비워 둔다. 세트 반복 수와 상위 % 한 줄에 쓴다.
- 로그인 유지 30일. 실패 5회 시 15분 잠금.
- 탈퇴·강퇴 시 운영자가 계정을 비활성화한다. 데이터는 삭제 요청이 있을 때만 지운다.

### 4.1 기능1 — 기록 단축 세트
**질문에 답한다: "1초 줄이려면 뭘 해야 하나?"**

입력: 종목(영법·거리), 현재기록(내 최근/최고 기록 자동), 목표기록 또는 "N초 단축".
출력:
- 목표까지 필요한 단축 시간과 비율 (예: 자유형 50m 32.40 → 31.40, 3.1%)
- **1초 단축 단위 처방표**: 단축 1초마다 필요한 운동 세트
  예) "레이스 페이스 25m × 8, 휴식 20초 — 주 2회, 6주"
- 세트마다 **목표 페이스(25m당 시간)와 인터벌**이 계산되어 있다
- 근거 한 줄 ("다이빙 이득 0.70초 보정" 등)

처방 방식 (**공식 + 코치 조정**):
1. 공식이 기본값을 만든다. v1의 `pace.ts`·`methods.ts` 엔진을 재사용하되
   "주간 플랜"이 아니라 **"단축 1초당 세트 묶음"** 형태로 출력을 바꾼다.
2. 코치(운영자)가 종목·단축 구간(0~1초, 1~2초, 2초 이상)별로
   세트 구성과 반복 수를 덮어쓸 수 있다. 덮어쓴 값이 있으면 그것이 우선한다.
3. 화면은 "공식 기본값"인지 "코치 처방"인지 항상 표시한다.

완주 개수 입력(v1의 ADR-0007)은 **v2 1차에서 제외**하고 백로그에 둔다.
입력 부담이 크고, 처방을 먼저 검증해야 한다.

### 4.2 기능2 — 나의 기록 추이
- 기록 입력 주체는 두 가지다. 같은 차트에 겹쳐 보이되 출처를 구분한다.
  - **개인 입력** (회원 본인): 날짜, 종목, 기록, 메모(선택)
  - **운영자 입력** (정기모임 기록회): 모임에 연결된 공식 기록
- 종목별 꺾은선 차트, **PB 마커**, 목표선. 낮을수록 위로 가도록 y축을 뒤집는다.
- 기간 필터: 3개월 / 6개월 / 1년 / 전체
- 기록표(날짜, 기록, 출처, 모임명)
- 운영자 입력 기록은 회원이 수정할 수 없다. 개인 입력은 수정·삭제 가능.
- 기록 입력 형식: 분·초·1/100초 칸을 따로 둔다 (`11200` 같은 연속 숫자 입력 금지).
  거리가 50m 이하면 분 칸을 숨긴다.
  — 구현은 v1 과 같이 **분 칸 + 소수점 있는 초 칸** 두 칸이다(`32.40`). 운영자가 30명을 넣을 때
  칸이 90개가 되지 않게 했고, 읽은 값을 칸 옆에 바로 보여줘 `32.4` 가 32.40 인지 확인하게 한다.
- v1의 50m 백분위 분포는 **보조 정보**로 한 줄만 표시한다 (상위 %, 출처 밝힘).
  분포가 없는 종목은 표시하지 않는다.

### 4.3 기능3 — 나인틴 훈련 참여 달성률
- 운영자가 **정기모임**을 만든다 (날짜, 장소, 종류: 훈련/기록회).
- 모임 후 운영자가 **출석 체크**를 한다. 회원 자가 체크는 없다.
- 달성률 = 내가 참석한 모임 수 ÷ 해당 기간에 열린 전체 모임 수
- 표시:
  - 이번 달 달성률 (큰 숫자 + 원형/막대), "8회 중 6회"
  - 월별 달성률 추이 (최근 6개월)
  - 모임별 참석 목록 (참석·결석)
- 모임 취소는 분모에서 제외한다. 가입 전에 열린 모임도 분모에서 제외한다.
- 월 목표 횟수는 v2 1차에서 도입하지 않는다 (모든 정기모임이 분모).

### 4.4 운영자 화면
| 기능 | 내용 |
| --- | --- |
| 회원 관리 | 등록, 표시명, 초대코드 발급·재발급, 비활성화 |
| 모임 관리 | 생성·수정·취소 |
| 출석 체크 | 모임 선택 → 회원 목록 체크 (일괄 체크, 늦은 수정 가능) |
| 모임 기록 입력 | 모임 선택 → 회원별 종목·기록 입력 |
| 처방 조정 | 4.1의 코치 조정 값 편집 |

출석·기록 입력은 **모임 당일 폰으로 30명을 2분 안에** 끝낼 수 있어야 한다.

## 5. 화면 구성

회원: **홈 / 세트 / 기록 / 출석** 하단 탭 네 개. 운영자는 하단 탭에 **운영** 탭이 하나 더 보인다.

| 화면 | 내용 |
| --- | --- |
| 로그인 | 초대코드 가입, 로그인. v1의 로고 시작 화면은 폐지하고 바로 로그인 |
| 홈 | 이번 달 달성률, 최근 PB, 목표까지 남은 초, 다음 정기모임 |
| 세트 | 기능1 |
| 기록 | 기능2 (차트 + 입력 버튼) |
| 출석 | 기능3 |
| 운영 | 운영자 전용 |

디자인 원칙
- **라이트 테마 하나**, 나인틴 블루(로고 색) 단일 강조색
- 첫 화면에서 숫자 하나(달성률 또는 남은 초)가 가장 크게 보인다
- 용어는 회원이 쓰는 말만 쓴다 ("강도 최상급/분량 중급" 같은 내부 등급 노출 금지)
- 폰 우선, 한 손 조작, 글자 16px 이상, 터치 영역 44px 이상
- 디자인 시안은 이 PRD 확정 후 별도로 진행한다

## 7. 비기능 요구사항

- **개인정보**: 이름·기록·출석만 수집한다. 신체 데이터(체중·키)는 받지 않는다.
  v1의 "신체 데이터는 기기 밖으로 나가지 않는다"(ADR-0002)는 신체 데이터를 아예 받지 않는 것으로 계승한다.
- 비밀번호는 서버에서 해시(argon2 또는 bcrypt)로만 저장한다.
- 회원 본인 데이터만 조회·수정 (서버 쪽 행 단위 접근 제어).
- 규모: 회원 30~100명, 동시 접속 10명 이하. 무료 티어로 운영 가능해야 한다.
- 모바일 웹(PWA) 우선. 앱스토어 배포 없음.
- 성능: 모바일 LTE에서 홈 화면 2초 이내.
- 계산(세트·달성률)은 순수 함수로 두고 테스트한다 (v1 방침 유지).

## 8. 기술 방향 (제안, 별도 ADR로 확정)

| 항목 | 제안 | 이유 |
| --- | --- | --- |
| 호스팅 | 정적 PWA 유지 + BaaS(Supabase 등) | v1 코드·배포 파이프라인 재사용 |
| 인증 | 초대코드 + 이름/비밀번호를 서버에서 처리 | 외부 로그인 연동 없음 |
| 엔진 | v1 `pace.ts` 등 재사용 | 검증된 계산 |
| 폐기 | ADR-0002(기기 내 저장), ADR-0004(서버 없음) | 서버가 생기므로 대체 ADR 필요 |

Supabase 기본 인증은 이메일/전화 기반이라 "이름 + 비밀번호"를 그대로 쓰기 어렵다.
**이름을 내부 가짜 이메일로 매핑**하거나 **Edge Function으로 직접 인증**하는 둘 중 하나를 ADR에서 정한다.

## 11. 열린 질문

1. **계수표**: "1초 단축 = 세트 몇 개"의 기본 공식을 v1 엔진에서 어떻게 뽑을지, 코치가 어느 종목부터 덮어쓸지. 코치와 한 번 앉아야 한다.
2. **출석 모임 종류**: 기록회도 달성률 분모에 넣을지 (4.3은 훈련·기록회 모두 포함으로 가정).
3. **기존 회원 데이터**: v1 사용자의 localStorage 기록을 가져올 방법이 필요한가 (JSON 내보내기 파일 업로드로 처리 가능).
4. **초대코드 방식의 보안**: 이름 + 비밀번호만 쓰면 비밀번호 분실이 운영자 부담이 된다. 회원 수가 많아지면 재검토.
5. **서버 비용·운영 주체**: 무료 티어 한도와, 운영자가 바뀔 때 관리자 권한 이관 방법.
6. **개인정보 동의**: 이름·기록 수집에 대한 동의 문구와 보관 기간.
